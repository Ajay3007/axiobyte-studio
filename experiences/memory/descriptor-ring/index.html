Descriptor ring

A circular array of descriptors that a driver allocates in host memory for one NIC queue. Each descriptor holds a buffer's address and a status — never the packet bytes.

Software and the NIC share the ring. Software fills descriptors with the addresses of empty packet buffers; the NIC takes them in order, writes each packet it receives into the buffer a descriptor names, and marks the descriptor done. The ring is circular only in how it is used: in memory it is an ordinary contiguous array, and after the last descriptor comes the first again.

What a descriptor holds

A buffer address, a length and a status — a few bytes, typically 16 or 32. The fields drawn are a schematic layout, not any real NIC's format, and no values are shown: the ring's structure is the same whatever it holds at a given moment. A single descriptor is a slot of the ring, never a separate thing: descriptors are reused around the ring and never leave it.

Head and tail

The head is the next descriptor the NIC will fill; the tail is how far software has refilled the ring. Between them are the descriptors ready for the NIC; behind the head are those it has marked done, waiting for software to collect them. Head and tail are indices — kept in registers on the card and in the driver — not pieces of the ring, so they are anchors here, not parts, shown at fixed, illustrative positions.

Where it lives

In host memory. A ring is an ordinary allocation in DRAM, not memory on the NIC; it may reside in host memory's descriptor region, where the Host Memory page draws one in its address map. This page shows the ring on its own.

What it refers to

Each descriptor refers to a packet buffer: storage in host memory's packet-buffer region, which is a part of host memory, not a separate model here. The reference is an address — it names the buffer, it is not the buffer, and it moves no data. The packet bytes reach the buffer separately, by DMA: the NIC writing memory over PCIe, which the NIC to host memory system shows. An mbuf, the DPDK structure that also holds a buffer's address, is a different thing again and is not modelled here.

Technical concept

descriptor_ring — “A descriptor ring is a circular array, prepared by software in host memory, where each slot points at a free buffer for the NIC to fill.” Its visual rule: a ring is never drawn holding the packet bytes.

Scope

This page shows what a descriptor ring is. It deliberately leaves out what happens to one at run time and what other parts of a system own: which descriptor points at which buffer at a given moment, concrete addresses, head and tail moving, which NIC queue a ring serves, who owns and allocates it, how the NIC fetches descriptors and writes them back, and mbufs and mempools. Real rings hold hundreds to thousands of descriptors; eight are drawn here.
